# Передача проекта и дальнейшая разработка

Разработка этой версии завершена; исходники опубликованы как самостоятельная отправная точка. Сборка 1.3.220 запускается с новой базой и нейтральными настройками. Рабочие данные и подключённые аккаунты не входят в репозиторий.

## Карта кода

- `repostbot/app.py` — HTTP-панель, авторизация администратора, CSRF, API, запуск и остановка.
- `core.py` — `Store` (SQLite, настройки, миграции, очередь и журнал публикаций) и `Worker` (обработка Telegram, маршруты и координация).
- `message_template.py`, `video_links.py`, `youtube.py`, `video_browser.py`, `vk_identity.py` — шаблоны и источники. `stream_series.py`, `repost_stats.py` — серии анонсов и статистика реальных доставок.
- `reply_turn.py`, `reply_context.py`, `speaker_identity.py`, `rich_reply.py` — сбор составных обращений, контекст и разбор ответа. `ai.py`, `model_router.py` — модели и ограничения ресурсов.
- `community.py`, `participant_roles.py`, `account_links.py`, `social_features.py` — участники, связи учёток, репутация, роли и звания.
- `scout.py`, `scout_transport.py` — отдельный Telegram-аккаунт через Telethon. Вспомогательные `scout_*` отделяют обработку истории, диалогов, тестов, профиля и отправок.
- `scout_twitch.py` — отдельное подключение Twitch. `scout_twitch_irc.py` — подтверждение входа, IRC, переподключение и отправка. `scout_twitch_browser.py`, `scout_cdp.py` — системный браузер, постоянный профиль и нативное управление.
- `twitch_ledger.py` — отдельный журнал сообщений/наград, метки времени, категории, экспорт. `twitch_bots.py` — точные исключения логинов. `twitch.py` — общий парсер IRC и прежняя интеграция Twitch; не создавайте второго владельца отправок.
- `conversation.py`, `quests.py`, `auto_quests.py`, `moderation.py`, `presence.py` — опциональные инструменты общения. `personal_roles.py`, `role_scenes.py`, `community_context.py`, `temporary_context.py`, `scout_report_context.py`, `sticker_context.py` — нейтральные точки расширения без заранее заданных людей, историй и наборов медиа.
- `speech*.py`, `sticker_*.py` — озвучка и администрируемый каталог медиа.
- `static/index.html`, `app.js`, `style.css` — интерфейс без сборщика. Используются общие подгруппы, поиск и открытие вкладки по выбранной настройке.
- `update.py` — допустимые файлы, проверка и применение ZIP; `build_release.py` — сборка релиза без рабочих данных.

## Локальная работа

Python 3.11+ (предпочтительно 3.12), зависимости в `requirements.txt`, тестовые — в `requirements-dev.txt`. Запуск и системные компоненты описаны в README. Для тестов учётные записи и ключи не требуются.

```sh
python -m unittest discover -s tests -v
python -m compileall -q repostbot tests
node --check repostbot/static/app.js
REPOSTBOT_BROWSER_TESTS=1 python -m unittest tests.test_panel_smoke -v
```

В тестовом наборе проверяются разбор IRC, подтверждение входа и восстановление соединения, отделение браузерного чтения наград, фильтр ботов, дедупликация, дата экспорта, сохранение сессии при обновлении, связи аккаунтов, статистика репостов и защита API. Наличие проверок не означает проверки входа в реальные Twitch/Telegram на каждой платформе. Для сетевых испытаний используйте свои тестовые аккаунты и чат; никогда не сохраняйте их токены в фикстуры.

## Данные и миграции

SQLite хранится под `DATA_DIR`; точное имя файла задаёт запуск приложения. `Store` и модули создают/дополняют таблицы при инициализации. Добавляйте миграции без удаления существующих записей, под `store.lock`, с транзакцией. Проверяйте запуск на новой базе и обновление с предыдущей версией. Перед ручной миграцией делайте копию всей папки данных при остановленном процессе.

Рабочая папка содержит настройки, ключи, Telegram-сессии, профиль Chrome, историю и медиа. Она не должна попадать в исходники, архивы и скриншоты. Используйте временные базы и вымышленные сообщения в тестах. При остановке сначала выставляйте `worker.stop`, затем закрывайте источники и пулы, и только после этого SQLite: фоновые задания не должны обращаться к закрытому соединению.

## Договорённости между модулями

- Авторизацию Twitch подтверждает протокол чата и ожидаемый аккаунт; загрузка cookie или HTTP 200 не достаточны. Перезапуск браузера сохраняет профиль; явный выход удаляет сессию.
- Параллельное чтение уведомлений браузера при IRC не получает права отправки и не сбрасывает состояние IRC. Учитывайте поколение подключения и канал; результат старого запроса не принадлежит новому каналу.
- Не повторяйте неподтверждённую отправку автоматически. Сохраняйте ID источника и доставки для защиты от дублей.
- Дата лога — Москва; используйте реальные временные метки IRC, если они корректны. Награда и текст сообщения — отдельные записи с общей ссылкой, где она доступна. Начальный DOM-снимок является базой, а не потоком новых наград.
- Не обещайте полную историю Twitch: IRC не отдаёт пропущенное, DOM видит только доступные уведомления. Не добавляйте автоматическое обучение или отправку лога внешней модели без отдельной настройки и задачи.
- Фильтр ботов — точные логины, плюс свой логин и пользовательские исключения. Не угадывайте бота по отображаемому имени.
- Автосвязь аккаунтов использует актуальные проверенные username, однозначность на каждой площадке и канонизацию регистра/разделителей. Не расширяйте её до произвольного похожего имени без механизма подтверждения. Ручные связи и запреты имеют приоритет.
- Статистика анонсов опирается на фактические доставки. Записи с несколькими категориями и без классификации учитываются отдельно. Значения отчёта не должна придумывать модель.
- Telegram-ограничение `/roll` для скрытого профиля сохраняется. Twitch `/roll` включается отдельно; автоматические разговоры и приветствие Twitch в этой версии приостановлены.
- Новые административные API защищайте существующими проверками сессии и CSRF. Не выводите секреты в события, экспорт, ответы API или консоль.

## Выпуск

Измените `version.json` и версию CasaOS, обновите README, выполните проверки и `python build_release.py`. Скрипт читает только разрешённые runtime-файлы и документацию, проверяет структуру пакета и печатает SHA-256. Папки данных, сессии и `.git` не пакуются. Добавление runtime-модуля требует проверки `update.REQUIRED`.

Проверяйте ZIP на отдельной установке с синтетической базой: сохранение настроек, ролей, очередей, сессий и пользовательских инструкций. Для Docker доступен production Dockerfile; полный образ требует скачивания браузера и системных пакетов.

## Ограничения передачи

Это крупный проект со встроенными миграциями и общим Worker. Нейтральные расширения намеренно пусты; собственные профили, сценарии и медиакаталоги настраиваются отдельно. При продолжении начинайте с конкретной задачи и её проверяемого результата; не включайте опциональные внешние действия автоматически. Интеграции зависят от доступности платформ и меняющихся протоколов.
